# Пользовательские сценарии Auto Offer

> Нормативный источник требований приложения. Функция допустима только при наличии scenario ID; приложение не должно предвосхищать ещё не реализованные сценарии.

## A. Каталоги

### A1. Первичная загрузка каталога

- **Цель пользователя:** подключить первый размеченный прайс.
- **Предусловия:** Каталогов ещё нет; подготовлен размеченный прайс.
- **Основной поток:** Оператор выбирает файл, проверяет сводку и добавляет каталог.
- **Альтернативный или ошибочный поток:** При ошибке файл не добавляется; оператор получает возможность повторить загрузку.
- **Ожидаемая обратная связь:** Показаны этапы загрузки и подтверждение сохранения.
- **Итоговое состояние данных:** Проверенный каталог доступен и включён.

### A2. Одновременное использование нескольких каталогов

- **Цель пользователя:** работать с ассортиментом нескольких поставщиков.
- **Предусловия:** Подключён хотя бы один каталог.
- **Основной поток:** Оператор добавляет дополнительные каталоги и видит общую сводку.
- **Альтернативный или ошибочный поток:** Ошибка одного файла не препятствует сохранению остальных корректных файлов.
- **Ожидаемая обратная связь:** Для каждого файла показан отдельный результат.
- **Итоговое состояние данных:** Все корректные каталоги сохранены независимо.

### A3. Включение и отключение каталога

- **Цель пользователя:** временно исключить или вернуть каталог.
- **Предусловия:** Каталог сохранён.
- **Основной поток:** Оператор меняет состояние каталога и видит новый статус.
- **Альтернативный или ошибочный поток:** Недоступный каталог нельзя выбрать для новой заявки.
- **Ожидаемая обратная связь:** Статус явно обозначен текстом и символом.
- **Итоговое состояние данных:** Выбор сохраняется для следующего запуска.

### A4. Обновление или замена версии прайса

- **Цель пользователя:** обновить прайс без потери рабочей версии.
- **Предусловия:** Каталог с тем же идентификатором уже сохранён.
- **Основной поток:** Оператор проверяет новую версию и явно подтверждает замену.
- **Альтернативный или ошибочный поток:** При отмене или ошибке проверки текущая версия остаётся.
- **Ожидаемая обратная связь:** Показано предупреждение и итог замены.
- **Итоговое состояние данных:** Только подтверждённая корректная версия становится текущей.

### A5. Удаление каталога с учётом используемых сессий

- **Цель пользователя:** удалить ненужный каталог осознанно.
- **Предусловия:** Каталог сохранён; на него могут ссылаться черновики.
- **Основной поток:** Оператор видит число ссылок, подтверждает удаление и при необходимости отменяет его.
- **Альтернативный или ошибочный поток:** При ссылках предложено безопасное отключение; отмена ничего не меняет.
- **Ожидаемая обратная связь:** Показаны последствия, результат и возможность Undo.
- **Итоговое состояние данных:** Каталог удалён либо отключён; ссылки черновиков не переписаны.

### A6. Просмотр и поиск товаров каталога

- **Цель пользователя:** управлять каталогом: просмотр и поиск товаров каталога.
- **Предусловия:** Оператор находится в подходящем этапе сценария; необходимые исходные данные доступны.
- **Основной поток:** Оператор выбирает действие «Просмотр и поиск товаров каталога», проверяет представленную сводку и подтверждает результат.
- **Альтернативный или ошибочный поток:** Если условия не выполнены или возникает ошибка, действие не портит ранее сохранённые данные и может быть повторено.
- **Ожидаемая обратная связь:** Интерфейс показывает текущее состояние, причину ограничений и доступный следующий шаг.
- **Итоговое состояние данных:** Сохраняется только явно подтверждённое состояние; связанные данные остаются согласованными.

### A7. Несовместимая версия taxonomy

- **Цель пользователя:** не допустить смешения несовместимых справочников.
- **Предусловия:** Выбран каталог с иной версией taxonomy.
- **Основной поток:** Система отклоняет каталог и объясняет несовместимость.
- **Альтернативный или ошибочный поток:** Оператор выбирает совместимый файл.
- **Ожидаемая обратная связь:** Указана причина и сохранность текущих данных.
- **Итоговое состояние данных:** Хранилище каталогов не изменено.

### A8. Каталог с позициями needs_review

- **Цель пользователя:** понимать объём каталога, требующий проверки.
- **Предусловия:** В каталоге есть отмеченные позиции.
- **Основной поток:** Оператор видит их количество в карточке и общей сводке.
- **Альтернативный или ошибочный поток:** Нулевое количество показывается явно.
- **Ожидаемая обратная связь:** Сводка различает validated и needs_review.
- **Итоговое состояние данных:** Каталог сохранён вместе с исходной разметкой.

## B. Заявки и сессии

### B1. Создание новой сессии из request bundle

- **Цель пользователя:** создать рабочий черновик по размеченной заявке.
- **Предусловия:** Есть корректная заявка и хотя бы один активный каталог.
- **Основной поток:** Оператор загружает заявку, проверяет строки, выбирает каталоги, задаёт название и сохраняет.
- **Альтернативный или ошибочный поток:** Без каталога или названия создание недоступно; ошибочная заявка не сохраняется.
- **Ожидаемая обратная связь:** Этапы и результат каждого действия видимы.
- **Итоговое состояние данных:** Создан постоянный черновик со снимками ссылок на каталоги.

### B2. Безопасная замена заявки

- **Цель пользователя:** безопасно заменить выбранную заявку до сохранения.
- **Предусловия:** На форме уже проверена заявка.
- **Основной поток:** Оператор выбирает другой файл; форма меняется только после успешной проверки.
- **Альтернативный или ошибочный поток:** Ошибка нового файла сохраняет прежнюю заявку и введённые данные.
- **Ожидаемая обратная связь:** Сообщение прямо указывает, что осталось сохранным.
- **Итоговое состояние данных:** В форме находится последняя успешно проверенная заявка.

### B3. Просмотр строк заявки до подбора

- **Цель пользователя:** проверить исходные строки до подбора.
- **Предусловия:** Заявка успешно проверена.
- **Основной поток:** Оператор просматривает текст, количество, единицу, класс и статус каждой строки.
- **Альтернативный или ошибочный поток:** Технические детали открываются отдельно и не заслоняют таблицу.
- **Ожидаемая обратная связь:** Показаны сводка, строки и признаки проблем.
- **Итоговое состояние данных:** Данные заявки не изменяются.

### B4. Обнаружение возможных повторов строк

- **Цель пользователя:** управлять заявкой и сессией: обнаружение возможных повторов строк.
- **Предусловия:** Оператор находится в подходящем этапе сценария; необходимые исходные данные доступны.
- **Основной поток:** Оператор выбирает действие «Обнаружение возможных повторов строк», проверяет представленную сводку и подтверждает результат.
- **Альтернативный или ошибочный поток:** Если условия не выполнены или возникает ошибка, действие не портит ранее сохранённые данные и может быть повторено.

# B5a: решения и обратная связь

Оператор явно обрабатывает **каждую** строку: выбирает конкретный товар (`selected_offer`) либо осознанно оставляет её без предложения (`no_offer`). Отсутствующая запись означает, что решение ещё не принято. Необязательная обратная связь хранится независимо от решения: outcome/cause, комментарий и, для совместимых outcome, полный `OfferRef` правильного товара.

После решений по всем строкам текущего запуска доступен AI JSON с исходной заявкой, полным результатом matcher, operator review и снимками упомянутых товаров. Feedback для экспорта не обязателен. Финальное подтверждение и пользовательский итоговый документ не входят в B5a и запланированы для B5b.

# B5b: завершение проверки

Сессия проходит из `draft` в `confirmed` только после общей проверки полноты и целостности latest run и SelectionState. Подтверждение фиксирует fingerprint, matching/selection revisions, counts и время. Confirmed-сессия доступна только для чтения; возврат в draft очищает confirmation, сохраняя run, решения и feedback. AI JSON 1.1.0 доступен для завершённого актуального draft и подтверждённого snapshot. Основной человеческий документ остаётся сценарием G1 будущего PR.
